## 4. Architecture Issues Found

### 4.1 Hardcoded `localhost:3100` in Client-Side Code

| Project | File | Issue |
|---------|------|-------|
| Project_Exp | `src/public/js/property.js` | 7 direct `fetch('http://localhost:3100/...')` calls |
| Project_Exp | `src/public/js/client.js` | 2 direct `fetch('http://localhost:3100/...')` calls |
| BB-DocEngine | `estimate-templates/index.html` | 9 direct `fetch('http://localhost:3100/...')` calls |
| BB-DocEngine | `TM_agreement-V5.html` | 1 direct `fetch('http://localhost:3100/...')` call |

**Impact:** Cloud migration will break these — they bypass the server proxy.
**Fix:** Route through local server's `/api` proxy (like `main-panel.html` does correctly).

### 4.2 Route Prefix Inconsistency

Some routes use `/api/` prefix, some don't:
- **No prefix:** `/qbo/customers`, `/qbt/users`, `/health` (used by TS_Latest, Project_Exp, BB-DocEngine)
- **With prefix:** `/api/qbo/customers`, `/api/health`, `/api/qbt/validate-labor-exact` (used by extensions, RevExp5, Binder_Exp)

Both patterns work in Mini_API_Bridge (it mounts routes both ways), but this should be standardized.

### 4.3 Shared Service Pattern (Good)

**QboService pattern** (shared between Project_Exp and BB-DocEngine):
- `qbo-service-v3.js` abstracts all bridge calls behind methods
- Constructor accepts `miniApiBridgeUrl` parameter
- Proper health check before critical operations

### 4.4 Best Architecture: CalExp5

- All calls through Express proxy (`/api/*` → `http://localhost:3100`)
- No direct client→bridge calls
- Run.bat auto-starts bridge if needed
- Clean separation of concerns

## 7. Cloud Migration Impact

### Routes Safe for Cloud (No changes needed)
All QBO/QBT/Batch/AI routes — these are purely HTTP proxies to external APIs. Moving the bridge to cloud doesn't affect them.

### Routes Requiring Client Updates
The 19 hardcoded `localhost:3100` references in Project_Exp and BB-DocEngine must be updated to use configurable URLs before cloud deployment.

### Chrome Extensions (Invoice_Validate2, Chase_Expense_Validator)
These already have configurable bridge URLs via popup settings. Users just need to update the URL to point to the cloud bridge.

### Best Prepared for Cloud
1. **Binder_Exp** — env var `VITE_MINI_API_BRIDGE_URL` (build-time configurable)
2. **CalExp5** — server proxy with `API_TARGET` variable
3. **RevExp5** — user-configurable port in Settings UI

### Needs Work for Cloud
1. **Project_Exp** — 9 hardcoded `localhost:3100` in client JS
2. **BB-DocEngine** — 10 hardcoded `localhost:3100` in HTML/templates + 22 debug scripts
